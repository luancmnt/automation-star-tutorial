Rule under test

From README.md and openapi.yaml (POST /checkout):

  • cash applies a 10% discount on the cart subtotal.
  • credit_card applies no discount.
  • paymentMethod is an enum: cash, credit_card.
  • An empty cart cannot be checked out, so the discount formula is not applied.

Partitions

Equivalence partitioning identifies classes of input that the rule treats the same way. One representative was chosen from each class. No boundary-value, pairwise, or decision-table cases were added.

Input Partition Class Representative Expected behaviour
paymentMethod P1 Valid — cash cash 201, discountRate 0.1, total = subtotal × 0.9
paymentMethod P2 Valid — credit card credit_card 201, discountRate 0, total = subtotal
paymentMethod P3 Invalid — not in enum paypal 400, no order
Cart state C1 Valid — non-empty Seed products (prod-1, prod-2, prod-3) Discount formula may run
Cart state C2 Invalid — empty Empty cart for Alice after prior checkout 400, no order

Finding

The discount rule matches the specification for every partition tested.

  • Cash on a payable cart: Mechanical Keyboard subtotal 120.00 → discount 12.00 → total 108.00 (order aaabb359-a926-4be7-bdee-d43f9d4fbe11).
  • Credit card on a payable cart: Headphones + two hubs subtotal 240.00 → discount 0.00 → total 240.00 (order 653058ac-9248-4932-9d26-9fd3cd264002).
  • Invalid payment method paypal: HTTP 400, paymentMethod is required and must be cash or credit_card.
  • Empty cart with valid cash: HTTP 400, Cart is empty. Add products to the cart before checkout.

No defects were observed. Expected API rejections (P3, C2) are recorded below as failure-path evidence; those test cases still passed because the API rejected them as specified.
